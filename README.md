## 🎯 项目初衷 (Manifesto)

你是否也经历过这些令人啼笑皆非的日常时刻？
- 走在路上刚掏出手机，手腕稍微一偏，手机陀螺仪便以迅雷不及掩耳之势判定为“扭动手机”，猝不及防为你推开电商百亿补贴的大门；
- 弹窗右上角的叉号仿佛是在视力表最后一行选拔出来的，尺寸微小且难以辨认，稍有不慎点偏半个像素，立即启动后台下载流水线；
- 红色横幅赫然写着“200,000元备用金即将失效”或仿冒微信未读红包，专挑防备心较低的长辈或注意力分散的用户下手；
- 明明充值了年度会员，打开 APP 依然要面对体贴的 5 秒开屏全屏推荐——关闭按钮甚至延迟 3 秒才慢条斯理地浮现。

不少人在被惊扰时暗下决心：*“这家公司的产品我坚决不用！”*  
然而，劣质营销恰恰利用了人类的**遗忘效应**：一段时间后，用户往往只记住了该品牌的“知名度与曝光量”，却遗忘了它曾粗暴打扰过自己的日常——**诱导投放由此达成了商业转化。**

**本项目旨在建立一份客观、公开、可查证的「移动端不良广告与诱导跳转留存名录」**：
1. **客观存证**：把每一次违规打扰记录成结构化数据，附带真实截图留存，让非体面的交互留下公开档案。
2. **理性避雷**：消费即投票。在日常消费与服务选购前搜一搜，把预算留给真正尊重用户的体面品牌。
3. **正向替代**：整理体面、清爽的开源与干净替代软件，协助大家逐步卸载肆意骚扰的宿主应用。
4. **社区共建**：汇聚广泛用户的真实日常样本，促使商业广告重新回归体面与克制。

## 🤖 自动化收录流程 (如何提交 Issue 自动生成 PR)

本项目已配置 GitHub Actions 自动化建档机器人：

1. **进入提交页面**：点击访问 [New Issue](../../issues/new?template=report_ad.yml)，选择 **「提交流氓广告/诱导跳转案例」**。
2. **按模板填写信息**：
   - **品牌名称**（必填，如拼多多、快手极速版、360借条等）；
   - **载体宿主 APP**（必填，如酷狗音乐、万年历等）；
   - **APP 版本号**（推荐填写，如 `12.0.1`，方便精准定责）；
   - **事发捕获日期**（选填，留空默认为提交当天）；
   - **勾选典型手法**（多选，如摇一摇、假关闭按钮等）；
   - **现场截图凭据（核心必须项）**：**在说明框中直接 Ctrl+V / Command+V 粘贴截图**，或拖拽图片上传生成 GitHub 图片链接。**无截图的提交将无法自动生成 PR**。
3. **机器人自动转换**：
   - 提交 Issue 后，GitHub Actions 机器人将在 30 秒内自动触发。
   - 机器人自动解析表单、下载或转录截图、校验数据格式并自动创建对应的 Pull Request。
4. **合并发布**：
   - 维护团队核实证据真实性后点击 Merge，系统自动同步更新 README 与在线检索站！

> ⚠️ **仓库管理员配置须知 (如自动 PR 未触发请检查此项)**：  
> 新创建的 GitHub 仓库默认限制了机器人创建 PR。请仓库所有者确认开启以下配置：  
> 1. 进入仓库 **Settings** -> **Actions** -> **General**；  
> 2. 滑到页面下方 **Workflow permissions**；  
> 3. 勾选 **「Read and write permissions」**；  
> 4. 必须勾选 **「Allow GitHub Actions to create and approve pull requests」** 并保存。
